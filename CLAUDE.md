# CLAUDE.md

## Project

Hullcracker is a real-time, gridless naval battle royale in the browser (RT prototype). One ship per player on a large circular ocean with islands. Everyone fights on the same water in real time: an authoritative 20Hz server simulation with client-side prediction. Two-tier fog of war (a true-sight bubble around your hull plus a rotating radar sweep that paints decaying phosphor blips), guns/torpedoes/mines with real firing arcs, kill-banked upgrade points, and a shrinking storm circle. Last hull floating wins. This branch replaced the previous turn-based hex game (which still lives on `main`); see README.md for the player-facing overview.

Stack: TypeScript monorepo (npm workspaces) — `shared` (pure sim), `server` (Colyseus 0.17), `client` (PixiJS 8 + Vite).

### Commands
```
npm run dev          # Colyseus server (:2567) + Vite client (:5173) via concurrently
npm run check        # lint + type-check (shared/server/client) + all tests (3817)
npm run lint         # ESLint (complexity=10 enforced)
npm test -w shared   # Shared sim tests (kinematics, geometry, ballistics, zone, mapgen, stats, offers)
npm test -w server   # Server tests (world sim, perception/anti-cheat invariants, match state machine, drones)
npm test -w client   # Client tests (prediction, snapshots, clock, HUD/feel pure logic)
npm run build        # Build order: shared → client → server
```

- The server game process listens on `:2567` (override with `PORT`); the Vite client dev server is `:5173`. Open the client URL in the browser.
- **Server must boot from `server/`** (or `--tsconfig server/tsconfig.json`): Colyseus schema decorators need that tsconfig.
- **Headless smokes** in `server/scripts/*.mjs` prove full flows over real sockets. They use dev-only room options the server only honors when `HC_DEV_OPTIONS=1` is set — production clients can never pass them.

### Architecture

Three workspaces with strict layering: `shared` (deterministic pure simulation, imported by both sides) → `server` (authoritative world + Colyseus room) and `client` (prediction + Pixi renderer). Both sides run the SAME shared sim functions, which is what makes client-side prediction match the server.

#### Shared (`shared/src/`) — deterministic sim, zero I/O, plain objects
- **index.ts** — single barrel re-export; declares `PROTOCOL_VERSION` (bumped on any wire-contract break).
- **constants.ts** — `CONFIG`: the single source of truth for every simulation tunable (map, three ship classes, vision/radar/sweep, gun/torpedo/mine, storm zone timeline, upgrade stacking, transport rate limit under `net`). Also `UPGRADE_IDS`, `UPGRADE_CATEGORIES`, `HEAL_CHOICE`.
- **types.ts** — the client/server wire contract: `InputMsg`, per-client frames, `OwnShip`, contacts, blips, game events, `MSG` channel names, `WelcomeMsg`/`ResultsMsg`, `WeaponId`.
- **math/** — vec.ts, angle.ts (`wrapPositive`), geom.ts (`segCircleHit` — the LOS primitive), rng.ts (`mulberry32` seeded RNG).
- **sim/ship.ts** — ship kinematics (`stepShip`, `ShipConfig`, hull endpoints).
- **sim/stats.ts** — `effectiveStats()`: THE server/client desync firewall. One pure function turns (ship class + upgrade counts) into every derived number the sim and HUD consume. Both sides MUST call it; nothing re-derives an upgraded stat ad hoc.
- **sim/offers.ts** — `rollOffer()`: pre-rolled upgrade offers (3 upgrades from 3 distinct categories), deterministic per RNG stream so an offer rolled at earn-time can never reroll.
- **sim/collision.ts** — boundary + ship-island resolution.
- **sim/shell.ts** — swept ballistic collision (`stepShell`).
- **sim/map.ts** — seeded deterministic HEIGHT-FIELD map generation (`generateMap`): builds the fBm field, rank-selects sea level, extracts coastlines and contours, and runs the navigability-grid validator; islands never travel on the wire, both sides rebuild the identical polygon coastlines (and height raster) from the seed.
- **sim/noise.ts** — integer-hashed permutation-table gradient noise, fBm, ridged multifractal, and a two-scale domain warp. Zero transcendentals (no `sin`/`cos`/`pow`/`exp`/`hypot`) so the field is byte-identical across V8/JavaScriptCore and `--jitless`/`--no-opt`.
- **sim/heightField.ts** — builds the height field (coarse pass + coastal-band refinement), the quantized Uint8 raster, and the max-height pyramid; O(1) sample + per-tile-ceiling API. Nothing reads the raster/pyramid yet — it's the retained substrate for a future radar-shadow pass.
- **sim/islandShape.ts** — the extraction machinery: per-map scratch grid, sea-level mask, lagoon closure (flood open water from the spawn ring, fill what it can't reach), marching-squares tracing.
- **sim/island.ts** — the single geometry seam every island consumer uses (LOS, shells, mine legality, spawn clearance, drone avoidance, collision push-out): mandatory bounding-circle broadphase (`isle.x/y/r`) before any exact polygon test, delegating all polygon math to `silhouette.ts`.
- **sim/zone.ts** — phased storm timeline (`zoneStateAt`/`zoneLiveState`/`rollZoneRings`/`isOutside`): three ring groups × clear/supply/reveal/close beats, offset-center rings (server-rolled, reveal-gated), terminal radius derived from truesight.

#### Server (`server/src/`)
- **index.ts** — `@colyseus/tools` boot; listens on `PORT` or `:2567`.
- **app.config.ts** — Colyseus app config; registers the `arena` room.
- **rooms/ArenaRoom.ts** — thin Colyseus adapter around `World` + `Match`. Bridges joins/leaves → roster schema, raw `"i"` input messages → World's input store, fixed steps → per-client frames. Applies the transport rate limit (`CONFIG.net.maxMessagesPerSecond`). Gates dev room options behind `HC_DEV_OPTIONS`.
- **rooms/roomOptions.ts** — `sanitizeRoomOptions()`: security gate for client-supplied room options.
- **rooms/schema/ArenaState.ts** — Colyseus `@type` schema (roster / `PlayerMeta`); only the roster syncs via schema — all spatial state flows through frames instead.
- **game/world.ts** — the authoritative simulation. Plain TS, ZERO Colyseus imports (fully unit-testable). Owns the single server clock; runs a 20Hz (50ms) fixed tick with a defined step order (inputs → ships → boundary → islands → shells → fire control → radar paint → sweep advance → respawns).
- **game/perception.ts** — per-observer visibility: the fog-of-war core and anti-cheat boundary (`observe()`). Two vision tiers (sight bubble + radar sweep), island LOS, and per-event visibility rules. Property-style invariant tests enforce that nothing outside sight ∪ this-tick radar paints can appear in any frame.
- **game/frames.ts** — per-client frame construction; the single chokepoint for everything spatial leaving the server (the `toClientView()` philosophy carried forward). Contacts/events come EXCLUSIVELY from `perception.observe()`.
- **game/inputs.ts** — input validation + latest-input store; the only path player intent enters the sim. Malformed messages are silently dropped (every field finite-checked, axes clamped).
- **game/match.ts** — match lifecycle state machine (waiting/gathering/countdown/live/results). Pure logic, zero Colyseus imports; the room implements its side-effect hooks.
- **game/drones.ts** — weaponless target drones that fill empty slots so a solo human still gets a battle royale. A drone is an ordinary ship driven through the same input pipeline; win checks are human-gated.
- **game/spawn.ts** — spawn-ring placement (max-min distance from existing ships, island-clear).
- **game/combat.ts** — compatibility re-export of gun fire control (moved into equipment/guns.ts).
- **game/equipment/** — `Equipment` interface + registry (index.ts): guns.ts, torpedoes.ts, mines.ts, shared ballistics.ts, ammo.ts. The gun is the permanently-selected default weapon; torpedo/mine are interim prime-next-shot skillshots. A click carries `input.slot` (0 gun / 1 torpedo / 2 mine — the resolved prime; the server keeps no priming state); every system's reload ticks every tick regardless of which slot is primed.

#### Client (`client/src/`)
- **main.ts** — bootstrap: build the Pixi stage, show the pre-join MENU (DOM) over the canvas, connect only on PLAY, then run the input→predict→render loop and the match-lifecycle UX (waiting/gathering/countdown → death → spectate → results → return to port).
- **state.ts** — mutable client game state; one-way data flow (server mirror → sim state → render views). Leaf-ish: no heavy app imports.
- **config.ts** — `CLIENT_CONFIG`: client-only render/feel tunables that never travel on the wire (gameplay-authoritative values stay in shared `CONFIG`).
- **app/loop.ts** — fixed-step sim + render loop driver.
- **net/** — connection.ts (`joinOrCreate('arena')`, welcome handshake, deterministic map rebuild from `welcome.mapSeed`), clock.ts (server clock estimate), snapshots.ts (snapshot buffer + contact interpolation), roomBindings.ts (message wiring).
- **sim/** — prediction.ts (own-ship prediction + reconcile-and-replay via the shared `stepShip` at the same 50ms dt), inputSampler.ts.
- **input/** — keyboard.ts (driving + upgrade actions), mouse.ts (aim within weapon arc + click-to-fire), telegraph.ts (9-detent set-and-forget engine orders).
- **render/** — PixiJS renderers: stage, camera, map, ships, contacts, projectiles, mines, fog (pre-baked texture composite), radar, phosphor (blip decay), zone, attention (Tier-1→Tier-2 attention seam), hud, firing, weaponArc, effects, shake, deniedFire, spectate, textures, fade.
- **ui/** — DOM overlays (canvas is Pixi; DOM only for chrome): menu, phase, results, killFeed, upgradeMenu (CTRL spend window), upgradeToast — plus chromeBar.ts, the PURE (zero-Pixi) composer for the top-center BR chrome bar that render/hud.ts draws.
- **audio/** — context.ts + tones.ts (WebAudio tone system, mute-aware).
- **util/** — banner, math, pool (object pooling).

### Code Quality Conventions
- **Cyclomatic complexity ≤ 10** — Enforced by ESLint (`complexity: ["error", 10]`). All functions must stay under this limit.
- **~500 LOC per file** — Soft convention, not enforced. Files may exceed this when the content is cohesive.
- **One-way client data flow** — server mirror (net) → sim state (prediction) → render views. state.ts is a leaf (no heavy app imports); render modules never drive net/sim.
- **Sim purity** — `shared/` is pure functions over plain objects (zero I/O); `server/src/game/world.ts` and `game/match.ts` have zero Colyseus imports so they stay unit-testable.

### Key Decisions
- **CONFIG is the single source of truth** — every gameplay-authoritative tunable lives in `shared/src/constants.ts` (`CONFIG`). Client-only feel knobs live in `client/src/config.ts`; promote a value to shared CONFIG the moment it becomes gameplay-load-bearing.
- **Deterministic shared simulation** — the same pure functions (`stepShip`, `stepShell`, `generateMap`, zone math) run on server and client. This is what makes client-side prediction agree with the authoritative world. `PROTOCOL_VERSION` (shared/src/index.ts, currently 33) records wire-breaking changes and IS a runtime join gate: `server/src/rooms/roomOptions.ts` (`protocolVersionError`) rejects a mismatched-or-missing client `pv` at matchmake time, before any seat is reserved.
- **effectiveStats() is the upgrade desync firewall** — (ship class + upgrade counts) → every derived stat, via one pure function both sides call. Server caches it on grant/spawn; client recomputes from `you.cls` + `you.upg`. Nothing may re-derive an upgraded stat ad hoc.
- **Upgrade offers are pre-rolled at earn-time** — a banked point carries a fixed offer of 3 upgrades from 3 distinct categories (`rollOffer`), rolled on the server's decorrelated upgrade stream and queued. Reopening the spend window can never reroll. Spend picks one upgrade (CTRL+1/2/3) or heals (CTRL+E, `HEAL_CHOICE`).
- **Authoritative 20Hz World, zero Colyseus imports** — `game/world.ts` owns the one server clock and runs a fixed 50ms step; `ArenaRoom` is a thin adapter. The room's only synced schema is the roster.
- **frames.ts is the single spatial chokepoint (anti-cheat)** — everything spatial leaving the server goes through per-client frame construction, and its contacts/events come EXCLUSIVELY from `perception.observe()`. Property-style invariant tests enforce that no contact/event references anything outside sight ∪ this-tick radar paints. Clients are never sent what their sight or sweep hasn't legitimately revealed.
- **Two vision tiers + one LOS rule** — true-sight bubble (`dist ≤ sightRange`, LOS-clear → live contacts) and radar (sight < dist ≤ radar, LOS-clear, beam crossed the bearing this tick → `blip` events). LOS = the observer→point segment crosses no island circle. Only ships paint on radar; phosphor decay is client render math (server keeps no blip history).
- **Per-event visibility rules** — shells/torps materialize at the sight boundary with current pos/velocity only (no range-derivable fields, so the wire can't be solved back to the muzzle); a boom's victim id is stripped unless the victim's center is sighted; damage is victim-private; upgrade/point events are self-private (enemy builds and point banks never ride on contacts).
- **Client prediction + reconciliation** — own ship is stepped locally each 50ms tick with a ring of un-acked inputs; every server frame drops acked inputs and replays the rest. Contacts are snapshot-interpolated (~-100ms). `P` toggles prediction ⇄ raw interpolation for debugging.
- **Fog is a pre-baked texture composite** — dark overlay with a feathered sight hole, conic sweep wedge, timestamp-decayed blips. DOM is used only for menu / results / kill feed; everything tactical is Pixi.
- **Match lifecycle is a pure state machine** — `game/match.ts` (waiting/gathering/countdown/live/results), zero Colyseus imports. At 2 human captains a 30s UNLOCKED join window opens (`gathering`, `CONFIG.match.joinWindow`) so more captains can pile into the same room; when it expires the 15s countdown arms and the room locks (`joinWindowMs <= 0` override = legacy immediate countdown+lock). A solo captain drives a weapons-safe ready room. Drones fill empty slots through the same input pipeline; the win check is human-gated.
- **Three ship classes, universal weapon fit** — Torpedo Boat (fast/light), Battleship (slow/heavy), Mine Layer (mid). Only hull dims, hp, and kinematics vary; every class shares CONFIG.gun/torpedo/mine. (The retired destroyer/cruiser/battleship prototype kinematics now live on as the drone envelopes, byte-for-byte, pinned by a shipClasses identity test.)
- **The universal standard gun (Eric ruling 2026-07-21)** — the permanently-selected default weapon: 360° (no mounts/arc), a single shot on a 5s reload (a 1-round pool, presented as a pure cooldown; 2.5s at a max global-cooldown build — Eric ruling 2026-08-04, was 3s base), that flies to the CLICKED point and BURSTS there in `burstRadius` (every enemy hull in range takes full damage; an early interceptor takes the smaller `contactDamage` and stops the shell with no burst, unless inside the would-be blast). Base range = radar range. Torpedo/mine are interim prime-next-shot skillshots.
- **Global cooldown reduction (Eric rulings 2026-08-04)** — there is ONE cooldown lever, not seven. `EffectiveStats.cooldownScale` (base 1.0, floored at 0.1) is multiplied into EVERY equipment's `reloadMs` exactly once, post-fold, in `clampStats()` — the sibling of the `rangeU` re-derivations, so `effectiveStats()` stays the sole derivation path. The universal `shipCooldown` card line (category `ship`, common ×5, DRILL SCHEDULE → PRACTICED CREWS → VETERAN RATINGS → BATTLE STATIONS → GUNNERY PENNANT) drives it **additively** (`add: -0.1`), so a full stack is exactly 0.5 — never `0.9^N`. All seven per-equipment reload card lines were deleted with it. Base gun reload rose 3s → 5s and base cannon reload 15s → 50s in the same ruling, so a max-cooldown build lands them at 2.5s / 25s. The scale is rounded to 3 decimals before the multiply: additive folding accumulates float dust, and because reloads tick down in 50ms steps and complete at `<= 0`, un-rounded dust costs a whole extra tick on every affected weapon. The seven `<equipment>.reloadMs` stat paths stay whitelisted so a future per-weapon card can still compose *before* the global scale.
- **Boon grants rescale in-flight reload timers (Eric ruling 2026-08-04)** — `World.applyBoon` → `rescaleReloadTimers()` scales a fitted slot's `reloadMsLeft` by `newReloadMs / oldReloadMs`, so a grant that shortens a reload preserves the PROGRESS FRACTION rather than making the player wait out the old timer. Pool counts are never touched, so no free round is granted; a boon that doesn't move reloads leaves every timer byte-identical. This supersedes the previous "finish the cycle you started" behavior, which became untenable once the cannon's base reload reached 50s.
- **One Equipment interface** — guns/torpedoes/mines all implement it (`game/equipment/`); each has its own ammo pool + reload timer (reload ticks regardless of which slot is primed). Torpedoes spawn with real bow clearance + an owner-only grace and outrun every hull so they can't self-hit at base speed.
- **Phased storm (Story 3.1)** — a shared, damage-only zone timeline (`sim/zone.ts`): three ~4-min ring groups, each running clear seas → reserved supply-drop no-op → next ring revealed → ring closes (one minute each), fully closed at ~12:00. Rings are offset-center circles rolled on a server-private stream (a per-room nonce — never derivable from the client-known map seed) and revealed to clients via ArenaState only from each group's reveal beat; the terminal ring radius is derived from truesight (2 × `CONFIG.vision.sight`). Stay inside or take damage; the storm never blinds any sensor.
- **Storm rendering (Story 3.2, Eric-ratified grammar)** — client-only presentation in `render/zone.ts` + `CLIENT_CONFIG.zone`: the live ring is a SOLID storm-readout edge, the revealed next ring a DASHED storm-readout telegraph (solid-vs-dashed = the non-color channel; the 3.1 phosphor safe ring is retired), the storm side is a full-area low-alpha fill whose outer radius is computed dynamically from camera↔ring geometry (bucketed, factor floor), and all edge strokes are screen-locked (world width ÷ camera zoom) across the 0.5×–1.5× zoom range. Reveal beat lands with one motion-gated 80ms flash (ring-identity keyed, never re-fires). The in-storm vignette breathes at `settings.pulseCapHz` and — via `render/attention.ts`, the first consumer of the attention-priority tier table — eases to a steady lit hold (240ms τ) while a Tier-1 threat channel (low-HP rail pulse, live denied pulse) is active. Story 4-8 owns the generalized tier system.
- **BR Chrome Bar (Story 3.3, Eric-ratified grammar)** — the top-center match register `n AFLOAT · n KILLS · T+mm:ss · <ring readout>` (`ui/chromeBar.ts` pure composer + `render/hud.ts` row, `CLIENT_CONFIG.chromeBar`), built entirely from data already on the wire (roster `alive`/`kills`, `zoneStartT`, ZoneView — client-only, no PV change). AFLOAT counts ALL hulls including drones (deliberate asymmetry with humans-only placement/results); T+ derives every frame from `serverNow − zoneStartT` (elapsed floors, countdowns ceil). Ring readout runs the continuous-countdown grammar (amendment 26, superseding amendment 20's reveal announcement): `RING CLOSES IN m:ss` to close start through EVERY pre-close beat — clear, supply, and reveal alike (the `RING REVEALED` register is retired; the on-water dashed telegraph carries the reveal) — with the amber exactly-1 Hz pulse (`min(1, pulseCapHz)`) in the final 10s, `RING CLOSING m:ss` to close end (no amber), then `RING CLOSED`; the segment wears storm-violet outside the amber window. The pulse is the attention seam's second Tier-2 consumer (eased hold at the lit keyframe under Tier-1; motion=off = static lit). The bar is in the ratified reveal-HUD survivor set: hudLayer texts drawn from both alive and spectate paths, visible whenever the zone timeline is anchored (`state !== 'idle' && startT > 0`), gone only at return to port. Replaced the 3.1 interim `zoneHud()` register.
- **The Endgame Guarantee (Story 3.4, Eric rulings 2026-08-02)** — radar range is DERIVED: `CONFIG.vision.radar = SIGHT * 2` (2 × base truesight = 660u; was the independent literal 650 — epic-3 amendment 22). Radar and the terminal ring radius (`terminalSightFactor × sight`) are now the same number by two independent derivations; shared constraint tests pin the pillar inequalities (radar = 2×sight, radar ≥ terminal ring radius, sight < terminal ring radius), so retuning truesight moves gun base range, star-shell flare range, radar paint, AND the endgame ring together. The no-stalemate bar is GEOMETRIC — no post-closure shrink, damage ramp, or forcing mechanic (amendment 24); evidence comes from the batch-sim `endgame` pilot (pacifist until `zonePhase === 'closed'`, then hunts — amendment 23), whose resolved matches structurally conclude past 12:00 inside the ~15:00 contract (`batch-sim-evidence-2026-08-02.md`; harness lengths are lower bounds, pacifist `unresolved` caps are structural).
- **The Gunnery Conversation (Story 4.3, Eric rulings 2026-08-04, amendments 15-20)** — gunnery stops being informationless. Three new signal-registry rows are DECLARED exceptions to the master perception invariant, each with its own independently-reimplemented oracle: `sp` (fall-of-shot splash) is self-private and gun-family only (wire kind `shell` — gun, cannon, star shells; never torpedo/mine), so a shooter's own misses render at the true impact point even in fog and bracket-and-walk fire works (FR16). `hc` (Hit Call) is self-private, covers ALL ordnance including mines (a Mine Layer learns remotely that a trap sprung), and carries NO severity channel of any kind — no amount, no hp, no victim id, no kill flag — with exactly one `hc` per shell resolution even when an AP shell pierces several hulls. `mz` (muzzle flash) carries NO identity for anyone — no shooter id, no hue, no weapon type — and is visible inside the DERIVED `CONFIG.vision.muzzleFlash` halo — the eighths ladder's 5/8 rung, `SIGHT * 1.25` = 412.5u since Story 4.9 (was `SIGHT * 1.5`, 495u) with island LOS (islands block this sensor exactly as they block every other, per the 2026-08-02 ruling); it fires for the gun family only (torpedoes stay the shipped "quiet weapon"). The flash is emitted at the shell's PRE-PRE-STEP origin — the true muzzle, not the sight-boundary reveal point — so it doubles as the Epic 1 D1 back-date mask: an observer inside the halo who can already see the shooter's hull sees the flash cover the back-dated spawn; an observer in the 330–412.5u annulus gets pure disclosure, since the shell itself is never revealed to them at all. The `boom` row's anti-leak rationale (`signals.ts:556`, *"hit confirmation beyond sight would leak contact presence"*) is KNOWINGLY SUPERSEDED for the owner-hit case only: the Hit Call is now that leak, deliberately, because the ratified decoy disambiguation oracle ("shooting a decoy produces no Hit Call") is only meaningful counterplay if you would normally get one at fog range. Victims and bystanders keep their existing rules unchanged — no new "an unseen shooter hit you" cue, no fog-piercing bloom for anyone but the shooter.
- **The Public Register (cycle 45, Eric rulings 2026-08-04, amendments 29-34)** — the kill feed is global. `sunk` becomes the FOURTH declared exception to the master perception invariant (joining 4.3's `sp`/`hc`/`mz`; `sm` and `fh` joined later as the fifth and sixth, and Story 4.6's bounty ruling confirms the count holds at six rather than growing to seven), gated by three clauses: **witnessed** (the historical rule, extracted verbatim and unchanged), **credited to you** (`sunkCreditedTo` — you learn that anything you sank went down, at any range, through any fog; amendment 17's Hit Call principle at its terminal case, and the single site a future *"or a teammate's kill"* extension changes), or **the victim is a combatant** (`!wreck.isDrone` — every captain's sinking reaches every client, by any cause including the storm). This is a RECONCILIATION, not a widening: the row already ratified *"sinking is public knowledge, its LOCATION is not"*, `syncRoster()` has always mirrored `alive`/`kills`/`deaths` to everyone every tick, and the payload is IDENTITY ONLY (`{k, id, by?}` — no position, class, hue, damage, or weapon). Location stays exactly as protected via a per-observer `seen?: true` stamped by `materialize()` precisely when the witness predicate holds; the client gates everything SPATIAL on it (sink plume, contact teardown), so an unwitnessed kill never draws a plume at a stale position. A fog kill now also reaches `recordSunk`, closing a shipped gap where it counted in the roster tally but was missing from the player's own "SHIPS YOU SANK". **Drones are NOT combatants** — the economy always said so (`CONFIG.xp.droneTierLevels` pays a fraction of a level where a captain pays a full one), so their sinkings reach only the witness and the killer, never the public. The matching win-condition change is DEFERRED to Story 6-3: `Match.checkWin()` is untouched and drones still gate the win, because the guard exists to stop a solo match insta-finishing at activation. `n AFLOAT` now counts CAPTAINS ONLY (superseding epic-3 amendment 19) while still counting the local player — the surviving half of that asymmetry. Feed capacity 6 lines / 8s TTL; presentation identical for witnessed and reported kills. PV 22 → 23.
- **Fractal terrain is an fBm height field (cycle 59, Eric ruling 2026-08-06, supersedes the cycle-51 capsule generator)** — cycle 51's "fractal islands" were a 1-3 point skeleton at uniform width with fractal noise painted on the OUTLINE: never able to produce a lobe, an arm, a hook or a bay, and carrying no elevation. Eric: *"Really, its that I wanted fractal island generation. You didn't really create fractal..."* `generateMap` now builds a layered integer-hashed gradient-noise field (fBm + ridged multifractal + a two-scale domain warp, in `shared/src/sim/noise.ts` + `heightField.ts`) over the map disc; thresholding it at a rank-selected sea level yields the coastline, and higher isolines of the SAME field yield RENDER-ONLY topographic contour bands (max 4, each stroked in its solid hypsometric colour and filled with a darker, less intense version — the shipped `#8B7520` yellow was never a ratified decision). **Zero transcendentals on the generation path** (no `sin`/`cos`/`pow`/`exp`/`hypot`) makes the field byte-identical across V8/JavaScriptCore and `--jitless`, retiring the cross-engine float-determinism risk the project had carried since cycle 51. **The star-shape invariant is RETIRED**: a thresholded field has arbitrary topology, so lagoon-freedom now comes from a generation-time closure pass (flood open water from the spawn ring, fill what it can't reach — the second phase must spread only through TIGHT water or a one-cell strait leaks the fill) instead of a shape clamp, and push-out moves from skeleton-normal to **nearest-boundary-point**. `Island.skeleton` is DELETED; `pole` (pole of inaccessibility) replaces it, and `core` is now measured about the POLE rather than the centroid, because on a hook the centroid falls in its own bay and would zero the LOS early-out on exactly the islands where it matters most. `Island` still carries `{x,y,r}` as its bounding circle for broadphase; every consumer still goes through the `shared/src/sim/island.ts` seam, and all polygon math still delegates to `silhouette.ts` — there is exactly one polygon library. Land coverage tightens from cycle 51's 3-5% band to the ratified **2-3%**; ~18 islands/map at 746 verts/map (vs ~1,500 shipped) — per-tick geometry gets cheaper despite far more coastline structure. `PROTOCOL_VERSION` 28 → 29 because the same seed now builds a different ocean.
- **The height raster + max-height pyramid is the radar-shadow substrate (Eric ruling 2026-08-06; CONSUMED by Story 4.11)** — the authoritative height data is a Uint8-quantized raster (14u cells) plus a 10-level max-height pyramid, NOT the contour polygons; contours are a rendering artifact only, never collided or LOS-tested. Eric: *"I am going to use those heights in a separate future pass so that islands create a realistic radar shadow... however this gets stored we should make sure that we will be able to run that math as cheaply as possible."* A hierarchical raymarch against the pyramid skips an entire empty tile in one test, so open water costs almost nothing; the raster/pyramid is built every generation (~118KB, never on the wire — both sides rebuild it from the seed). Shipped unread for nine cycles because retrofitting the storage later was the expensive path — that bet paid off in cycle 68.
