### TypeScript 7, what is actually known (2026-10-24)

- Released 2026-07-08 as a Go port; `npm install -D typescript` installs the native `tsc`. 7.0 ships **no JavaScript compiler API**; 7.1 is to ship "a new (and different) API". The announcement's exact layout for tooling that needs the API: `"@typescript/native": "npm:typescript@^7.0.2"` + `"typescript": "npm:@typescript/typescript6@^6.0.2"` (`@typescript/typescript6` exposes `tsc6`, so `tsc` stays 7.0).
- Hard errors in 7.0 (deprecations in 6.0): `target es5`, `downlevelIteration`, `moduleResolution node/node10/classic`, `module amd/umd/systemjs/none`, `baseUrl`, `esModuleInterop: false`, `alwaysStrict: false`, the `module` keyword for namespaces, `asserts` import attributes, CLI file paths when a `tsconfig.json` exists (unless `--ignoreConfig`). New defaults: `strict: true`, `module: esnext`, `target` = one before esnext, `types: []`, `rootDir: ./`, `noUncheckedSideEffectImports: true`, `stableTypeOrdering: true` (cannot be turned off), `libReplacement: false`. Our `tsconfig.base.json` (`ES2022`, `ESNext`, `bundler`, `esModuleInterop: true`, `strict`, `composite` per workspace, `declaration` + `declarationMap` + `sourceMap`) trips none of the removals; the `types: []` default is the one that bites (server needs `["node"]`).
- `--build` gains `--builders` (parallel project-reference builders, experimental); we run plain `tsc -p` per workspace in dependency order, not `-b`.
- **Unknown and gating:** whether the native compiler emits legacy `experimentalDecorators` with `useDefineForClassFields: false`. Not mentioned in the announcement, the typescript-go `CHANGES.md`, or anything found. `@colyseus/schema` 5's README: decorators are "still supported" but the library is "moving away from decorators due to ecosystem compatibility issues: they depend on the legacy `experimentalDecorators` implementation and `useDefineForClassFields: false`, which conflict with modern toolchain defaults". Task 4's emit diff decides it; the fallback is Question 2's.
- typescript-eslint: 8.72.0 peer `typescript >=4.8.4 <6.1.0`; forcing TS 7 gives ERESOLVE and then an import-time "does not support TS 7.0" throw. Native-backend PR #12803 (opt-in `parserOptions.projectService.EXPERIMENTAL_backend: 'native'`, IPC round-trips to a `tsgo` process, ~1.5× slower) targets 7.1 and is a draft. Our lint is NOT type-aware (`tseslint.configs.recommended`, no `parserOptions.project`), so it only needs the 6.0 API to parse.
