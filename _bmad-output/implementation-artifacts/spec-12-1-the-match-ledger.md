## Intent

**Problem:** Every finished match already builds a complete server-only `MatchRecord` (`server/src/game/matchRecord.ts`) and hands it to a `NullWriter` (`server/src/game/accountWriter.ts`), so nothing survives the match. Eric wants the data *"strictly for collecting match data right now so I can see trends, balance, and tune bots"*.

**Approach:** A floor story with no player-visible change. An in-process `server/src/ledger/` module writes each record to Postgres through **plain Drizzle** (stable `drizzle-orm` + `postgres`, with PGlite for tests and local dev). `createAccountWriter()` returns the real writer when `DATABASE_URL` is set, otherwise the `NullWriter`. `render.yaml` declares the **staging database only**.

**Eric rulings 2026-11-18 (this run; recorded as epic-12 amendment at PR time):**
- (a) **Plain Drizzle, not `@colyseus/database`.** The Colyseus docs' "bring your own database" path. The kit creates its own users/configs/saves/leaderboard tables with no off switch and pins a pre-release Drizzle. This supersedes the 2026-10-25 data-layer clause "Render managed Postgres + `@colyseus/database`" for 12.1. The Postgres half stands.
- (b) **Staging database only in this PR** (`hullcracker-dev-db`). Production's database and `DATABASE_URL` come in a later PR, after staging QA. This supersedes the AC's "both databases in THIS PR". Render reads `render.yaml` from `main`, so the staging database is created by the development→main release Eric runs right after this merges. Production gets the code with no URL, so its ledger stays OFF.
- (c) **Every finished match is written**: standard queue, Solo vs AI and private lobbies. The record's `mode` and each participant's `role` let 12.2 filter. Aborted or abandoned matches never build a record (existing latch), and that is unchanged.
- (d) **Privacy policy:** update the existing general copy to say match data is saved. The sentences that the ledger makes false get corrected; no new section is added.
- (e) **Build order is Eric's:** 12.1 runs now, concurrent with 12.3 and 12.4. This supersedes amendment 1(d)'s "12.3 → 12.4 → 12.1 → 12.2".

## Boundaries & Constraints

**Always:**
- The ledger NEVER takes the game down. No `DATABASE_URL` means the `NullWriter`, byte-identical to today. If the URL is set but the database is unreachable or a migration fails, the process still starts with the writer OFF and logs `ledger.disabled { reason }` exactly once. The `reason` is a short category; the connection string is never logged.
- Nothing on the tick awaits the writer. `ArenaRoom.handOverRecord` stays fire-and-forget and unchanged in shape.
- Writer: an in-process FIFO, one record at a time, retry once, then count it as failed. Each record is written in ONE transaction; retries are idempotent through primary keys (`ON CONFLICT DO NOTHING`). The queue has a bounded depth: over the cap, a record is dropped and counted as failed. `flush()` drains the queue with a time bound, and Colyseus's graceful shutdown calls it on SIGTERM, so a Render redeploy does not lose the matches in flight.
- **No callsign and no account column.** `ParticipantRecord.name` is dropped at the row mapping. The participant id stored is the record's opaque `id`. `userId` is not a column (Epic 14 adds it).
- Tables `matches`, `match_participants`, `match_hands` mirror the record AS BUILT TODAY:
  - match: id, mode, PV, game version, ended-at, activated-at, duration, endedBy, outcome, winnerId
  - participant: id, role, hullId, shift, placement (0 = countdown leaver), kills, damageDealt, beaconXpMs, dropsTaken, cards in fit order, bankedLevels, indexBonus
  - hand: ordinal, dealtAtMs (T+, may be negative), offered, taken, takenAtMs, redrawn
- Migrations are checked-in SQL under `server/drizzle/`, generated by `drizzle-kit generate` and applied at boot by Drizzle's migrator (never auto/push). Every new dependency is pinned exact. Bots and humans are written alike.
- `HC_DEV_DB=pglite` runs the real schema on file-backed PGlite (`server/.pglite/`, gitignored). `DATABASE_URL` wins if both are set. Plain `npm run dev` is ledger-OFF. Server tests run the real migrations on in-memory PGlite.
- Every log line obeys the PII rule: no names, no row values, no connection strings, and error text only through `describeError` with any URL redacted.
- `game/world.ts` and `game/match.ts` keep zero persistence imports; `game/` gains no imports of `ledger/`.

**Block If:** a required Render Blueprint field for the database cannot be confirmed from Render's own docs; a dependency's current version fails against Drizzle's driver with no stable alternative; a change would need `PROTOCOL_VERSION` or any client wire change.

**Never:** declare the production database or production `DATABASE_URL`; mount `@colyseus/database` or `@colyseus/auth`; add a web UI, admin console or report script (that is 12.2); add a persistent disk; write in-game copy; touch `CLAUDE.md`; bump PV.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|---|---|---|---|
| No store | no `DATABASE_URL`, no `HC_DEV_DB` | `NullWriter` installed; no ledger log, no DB import cost | — |
| Happy write | store up, match finishes | 1 `matches` row + N participants + all hands in one tx; `ledger.write.ok {matchId, rows}`; `writeOk`+1 | — |
| Store down at boot | URL set, connect/migrate fails | server boots; writer OFF; `ledger.disabled {reason}` once; records are dropped silently with no per-match spam | no throw out of boot |
| Transient write fail | first attempt throws | second attempt succeeds; written once (PK idempotent) | — |
| Persistent write fail | both attempts throw | `ledger.write.failed {matchId}`; `writeFailed`+1; queue continues | never rejects into the room |
| Queue overflow | depth at cap | new record dropped; `writeFailed`+1 | logged once per overflow burst, no spam |
| SIGTERM | records queued | flush drains (time-bounded) before exit | timeout logs count left |
| Countdown leaver | placement 0, negative T+ hands | written as-is | — |
| Draw | `winnerId` '' | stored as-is | — |

## Design Notes

The port is chosen synchronously at module load, but the store opens asynchronously. So `LedgerWriter` exists at once and its queue waits on `ready`; records that arrive before `ready` are queued. If `ready` rejects, the writer flips to disabled, drops its queue, logs `ledger.disabled` once and from then on behaves like the `NullWriter`. A record that fails twice is lost by design: the game never depends on the ledger.
