# Epic 12 Context: The Ledger

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Give the operator (Eric) a persistent, anonymous store of every finished match so he can see trends, balance and bot behavior from games that include human players, and a script that reads it back in the batch-sim harness's report shapes. The server already builds a complete server-only match record at each finished match and hands it to a null writer; this epic mounts the first real store behind that port. The epic also carries two player-visible side stories added 2026-11-18 (an in-game UI pass and an airdrop / radio beacon change), both gated on a design sitting with Eric.

## Stories

- Story 12.1: The Match Ledger (floor story, no player-visible change)
- Story 12.2: Reading the Ledger
- Story 12.3: The In-Game UI Pass (side story, design sitting first)
- Story 12.4: Airdrops and Radio Beacons (design sitting first)

Build order: 12.3 -> 12.4 -> 12.1 -> 12.2 (12.4's placement is the agent's assumption, not ruled).

## Requirements & Constraints

- The ledger never takes the game down: absence-gated on `DATABASE_URL`; without it the game is byte-identical and the writer is the null writer. With it set but the DB unreachable or a migration failing, the process still starts with the writer off and logs `ledger.disabled { reason }` once. Nothing in a tick ever awaits the ledger; a failed write is a log line plus a metric.
- Every row is anonymous: no callsign, no account column (`userId` stays null; the column belongs to Epic 14). Bots and humans are written alike; role distinguishes them.
- PII rule for logs: never log tokens, subject ids, callsigns or loadout contents. Privacy policy copy gains exactly one sentence saying match results (hull, gun, placement, cards) are stored with no name attached.
- No persistent disk on either web service; Render managed backups only. A dependency lands in the story that mounts it.
- `/metrics` gains `ledger.writeOk / writeFailed / queueDepth`; logs gain `ledger.write.ok { matchId, rows }` and `ledger.write.failed`.
- 12.2: report functions are pure over plain rows, unit-tested on fixtures; output is text in the harness's register, filterable by game version, date range and mode; no web UI or admin console; nothing runs unprompted; documented beside the balance-sim how-to. No `game/` changes, no PV change.
- 12.3 / 12.4: every tweak is unruled until Eric names it at the sitting; never invent mechanics, numbers or copy. Visual candidates are rendered to an artifact for his yes before commit. Readable values stay at least 13 px at 1080p; no in-game copy unasked. GDD is stamped only with what he ruled; How-to-Play copy is his.

## Technical Decisions

- Data layer: Render managed Postgres plus `@colyseus/database` (Drizzle + `postgres`, already in `server/package.json`, first mounted here). `drizzle-orm` pin is exact. Do not wire Colyseus auth/plugin tables; never use the auto-mount / `applyRouterDefaults`.
- `server/src/ledger/` is an in-process module mounted once in `app.config.ts`; `createAccountWriter()` returns the real writer when `DATABASE_URL` is set, else the `NullWriter` (port in `server/src/game/accountWriter.ts`, record from `matchRecord.ts`). Nothing under `game/` imports it; `world.ts`/`match.ts` keep zero persistence imports.
- Tables `matches`, `match_participants`, `match_hands` mirror `MatchRecord` (match-level, per-participant, per-hand fields).
- Migrations: checked-in SQL under `server/drizzle/` generated by `drizzle-kit`, run at boot, never `"auto"`.
- Writer: in-process FIFO, retry once, `flush()` on SIGTERM.
- `render.yaml`: `databases:` entries `hullcracker-db` and `hullcracker-dev-db` (region oregon, smallest paid tier), `DATABASE_URL` via `fromDatabase.property: connectionString`, landing in the same PR as the code that reads them, never ahead (Blueprint autoSyncs on main and bills on merge). Staging gets its own DB so the writer is QA'd there.
- Local dev and server tests run the real schema on PGlite (`HC_DEV_DB=pglite`); plain `npm run dev` is ledger-off.
- `PROTOCOL_VERSION` does not bump for 12.1/12.2. For 12.4: sim lives in `shared` + `CONFIG`; a wire or client-read CONFIG change bumps PV; any new spatial event goes through `perception.observe()` with an invariant line (no seventh exception); bots stay functional.
