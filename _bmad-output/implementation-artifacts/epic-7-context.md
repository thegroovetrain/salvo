## Requirements & Constraints

**Release gate (7.8):** current Chrome/Edge/Firefox/Safari; 1366×768 floor viewport with corner anatomy intact and no mono type below 9 px (the floor survives the Chromebook retirement independently); nothing debug ships (client dev tools behind `import.meta.env.DEV`, server dev behavior behind `HC_DEV_OPTIONS`, no prod `P` toggle); `loadTest.mjs` is **BUILT, not invoked** — it does not exist, the batch-sim load-test leg died with the drone-fill deletion and only the bot-evaluation leg was rebuilt — then proves the deployed tier survives a connection spike with `/metrics` confirming tick health; the unauthenticated solo-create cost vector is **RULED** (per-IP create throttle, global concurrent-solo ceiling, or explicit acceptance); `npm run check` green, `PROTOCOL_VERSION` consistent; and the full pipeline (home → queue → match → death → ad break → requeue) passes a manual run on **the production service (singular)**.

**Gate topology (amended 2026-08-21):** with 7.7 deferred there is no new topology to verify — the gate runs against the **single Render web service**, the topology every prior cycle already exercised, plus the **staging environment added at cycle 127** (`hullcracker-dev` on the `development` branch, password-gated via `HC_STAGING_KEY`, noindexed, analytics/ads absence-gated off). The development flow is feature → `development` → manual QA on staging → `main`. Two staging blind spots are structural: performance (starter tier vs pro) and the analytics/ads modules, which never run on staging and need a production smoke after merge.

**Scale posture:** beta runs a **single vertically scaled** game-server instance. Horizontal scale-out stays an injectable deploy-time knob but is explicitly not beta work. **Render autoscaling must never be enabled** — no WebSocket sticky sessions; it would break matchmaking.

**Standing budgets:** frame budget 16.6 ms = sim ≤ 3 ms + render ≤ 10 ms + headroom ≥ 3.6 ms on the stamped reference MacBook, in a fully populated match; cold load → interactive home under ~10 s with ad/analytics/consent scripts counted and fonts not blocking first paint. A budget breach is fixed at the offending system — never by cutting a ratified feature without Eric's sign-off.

## Technical Decisions

- **The planning artifacts are downstream of Eric.** They record what he wanted when written; when he says otherwise the doc is simply out of date. 7.6 made the docs describe the shipped game; do not argue a written clause back against a ruling.
- **The 7.7 deferral is cheap by construction.** The client-side seam already ships: `net/connection.ts` resolves the WS endpoint as `VITE_WS_URL` override > dev default `:2567` > same origin — so a future split touches only server/infra, never `shared/` or the wire contract. The story text stands in epics.md as the revival brief; revival tripwires are in `deferred-work.md`. Do not pre-empt the split (`render.yaml` is live configuration — the cycle-127 environment split is not a service split).
- **Versioning:** the "0.17.X until all 7 epics complete" ruling STANDS — 7.7 would have retired it and 7.7 is deferred, so beta ships as `0.17.X` (tree at 0.17.130). `PROTOCOL_VERSION` (currently 49) stays the runtime compatibility gate, independent of the release version.
- **The ad seam is retargeted, not retired.** The `PortalAdapter` interface keeps its name and never-throw / always-settle contract; the concrete implementation is the AdSense Ad Placement API. Game code never imports an ad SDK directly. A blocked ad script fires **no callback at all**, so return-to-port may never be gated on one.
- **Observability to lean on:** structured stdout logging with match/room/tick context, and the typed `/metrics` route (rooms, players, tick-duration p50/p95/max, message rates). **There is no client perf overlay** — Story 7.1 built a `--mode perf` production build plus headful captures instead, with the audit record under `implementation-artifacts/perf-gate/`.
- **Procedural-only assets** (vector linework + synthesized WebAudio tones) remain binding; the constraint outlived its portal justification and now stands on the load budget.
- **Known gate flake:** `radarHeatmap.test.ts` fails intermittently and predates current work — `npm run check` can go red on a clean tree; do not let re-run-until-green mask a real regression.
