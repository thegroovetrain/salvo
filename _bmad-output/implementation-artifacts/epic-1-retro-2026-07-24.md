## What Went Well

1. **The spec contract held: 1 intent_gap and 0 bad_spec across 13 stories.** Reviews found real bugs, but almost never found the spec pointing at the wrong target. The one intent_gap (1.3's collision mechanism provably unable to meet its own overlap-free AC — 97u teleports) was the epic's hardest moment and still landed same-day because Eric's live rulings replaced the revert-and-halt protocol.
2. **The adversarial review gate caught every high-severity defect before production.** 15 highs, all real, all patched with regression tests proven-to-fail-without-the-fix: the TB mineAmmo spend crash (1.6), the firer going blind to its own flare-revealed projectiles (1.7), three wire-level decoy unmasks/input losses (1.8), a silent denial inside the anti-silence mechanism itself (1.10), first-run Enter insta-picking a class (1.14). Cross-model value is documented repeatedly — Codex uniquely confirmed traces in 1.2/1.3/1.14, and patch-round re-checks caught residuals twice ("patch-of-a-patch").
3. **Precedent compounding was the epic's engine.** The registry chain (weapons → SIGNAL_REGISTRY → EQUIPMENT → burst-as-a-row); 1.6's `actSeq` ability channel and `boostedKinematics` shared-pure-helper-per-tick pattern (reused by 1.7, 1.8, 1.10); the `counterIntel` seam planted with an earmarking comment stories before 1.8 landed the decoy exactly on it; 1.4's per-weapon hit rules reused by the cannon; the perception oracle growing new permanent laws each story (owner-zone rules, blip-coexistence rejection, payload-pure ordering, owner-only denials).
4. **Non-blocking design escalation worked in every story.** All Eric gates — including the two GDD-flagged 1.8 gates (mine rework + Decoy Buoy) — resolved live, pre-implementation, or via mid-run AskUserQuestion. Zero recorded blocked time on a design gate across the epic. The Q&A-before-implementation pattern (1.7: "every design question surfaced to Eric BEFORE implementation") is the ideal to keep.
5. **Debt bookkeeping matured into a working system.** Interregnum warts were named at birth with a death date ("dies with Epic 2 economy"); 1.10 was a purpose-built debt-payoff story that closed three ledger entries; the ledger triage passes (07-18, 07-23) kept it a decision queue, not a landfill.
6. **Test infrastructure as law:** golden-frames byte-identity as the refactor spine (written first in 1.1, audited line-by-line at every deliberate regen), CI-by-construction registries (a row without a test breaks the build), "prove the test bites" via intentional mutation/probe/scaffolded-old-implementation, and 1.5's harness that debugged its own story's spec wording.

## Challenges & Growth Areas

1. **Client and DOM code is where quality dips — the highs moved with the work.** Server/perception code, guarded by the oracle and goldenFrames, produced few highs; client threading/render/prediction seams produced most of them (1.6 phantom boost tick, both 1.7 highs, 1.8 press collapse, 1.10's whole cluster), and DOM chrome was worst of all — 1.14 shipped 1 high + 6 mediums, all in headline UI flows. Adversarial review is currently calibrated to networking/perception/lifecycle; the code that needs it most in Epic 2 (input scheme, hotbar, settings — all client UI) is exactly this weak zone.
2. **The epic-context recompile erased ratified decisions THREE times** (1.7 review patch, 1.11, 1.13 — restored from git twice). Root cause: step-01 regenerates `epic-N-context.md` purely from planning artifacts, discarding review-patched corrections; ledgered as a workflow hazard in 1.13. **It will bite Epic 2's context file identically unless fixed before the first Epic 2 story compiles.**
3. **"Unseen in a browser" debt accumulated all epic.** Every visual story shipped without a browser pass (dev server is Eric-managed by standing rule). The one post-merge reversal — 1.14's class-card fantasy lines + GUN row, invented from a stale gunboat-era mock, surviving spec, dev, AND review until Eric's eyes caught it ("I never wanted that") — is the exact failure mode this gap predicts, and the "artifacts contain assumptions" principle warns about.
4. **Design docs are systematically behind shipped reality.** Every late story generated Eric-gated doc-sync ledger entries (UX-DR6/7, card-scrim typo, 14-char cap, contested-hoist rejection, class-card ruling, home mock batch, GDD aim-vs-deny-gate wording). Epic 2 specs will compile from these docs; stale inputs produced the 1.14 reversal once already.
5. **Tautological tests — three occurrences** (1.11 token pins mirroring the implementation, 1.12's uniqueness test, 1.14's ambient self-copy detector). Reviews converted each into external-truth pins; the class of bug is now a named review checklist item.
6. **Story sizing creep continued from Epic 0:** `oversized` on nearly every spec, `multiple-goals` on 1.4/1.5/1.14 — and those three carry the epic's highest patch counts. Epic 0's retro flagged the trend; it did not reverse.
7. **The follow-up-review loop never closes.** Epic 0 left item #4 undecided; Epic 1 added 11 more `followup_review_recommended` flags. Either the follow-ups happen, or the flag is noise — it currently means nothing.
8. **Lifecycle-boundary state resets remain a standing bug family** (1.6 sinkShip vs boostUntil, 1.10 clearActivations vs dedup keys) — death/respawn/spectate/reconnect boundaries should be an explicit review checklist line.

## Key Insights

1. **Move the heavy review gate to where the code is.** Epic 0 concluded adversarial review earns its cost on networking/perception/lifecycle; Epic 1's data says the same gate is now most needed on client UI state machines. Epic 2 is 40% UI stories (2.1–2.4).
2. **Live rulings beat revert-and-halt.** 1.3 proved the escalation protocol can bend without breaking: Eric's live rulings unblocked a halted story same-day, and the verbatim-quote discipline kept deferred rulings from drifting.
3. **Deception/anti-cheat features need wire-level adversarial review specifically** — 1.8's two surviving tells (coexistence, ordering) were invisible to unit tests and found only by hostile frame reading; the oracle then made them permanent laws.
4. **Compiled context files are not source of truth and must not silently regenerate.** Ratified corrections must live somewhere regeneration cannot reach, or regeneration must be content-aware.
5. **The latch-retry pattern** (1.12 hueLatch, 1.13 plate latch) is now the established answer to roster-sync races — any render latching roster data at spawn needs it.
6. **Recon-before-build shrinks stories** — 1.13 proved its silhouette ACs already held by construction and became the epic's cleanest story.
