## Build cycle 255 — Story 13.1 Crawlable Pages (0.20.13, PV 115 unchanged; `spec-13-1-crawlable-pages.md`)

3. **ONE VERSION OF EVERY PAGE.** Eric 2026-11-24, during `/gds-dev-story 13.1`, verbatim: *"I don't want two versions of the same thing. The home page doesn't need to be a game scene, that's only used for the background."* Asked whether the same rule covers How to Play and Privacy (AskUserQuestion): **"Yes, all three."**
   - (a) **The served HTML IS the page; JavaScript adds only what needs JavaScript.** Nothing is built twice, nothing is deleted-and-redrawn. **Supersedes** Story 13.1 AC 6's reading of record ("the prerendered block is removed and the live tree replaces it"), the AC 17 "composer equality" bullet (there is no second tree to compare), and AC 9's "BACK TO PORT stays a `<button>`".
   - (b) **How to Play / Privacy:** the build writes the whole styled page (`ui/pageMarkup.ts` + `how-to-play/pageMarkup.ts` / `privacy/pageMarkup.ts`; stat tables and glyphs included; the `--hc-*` theme vars in `<head>` from `theme.ts` `themeVars()`, the one list `injectTheme` also reads). At runtime `ui/page.ts` `attachPage` only binds ESC → home, Space on the back link, and `pagehide` (the bfcache `persisted` trap kept; real teardown unbinds and no longer removes the page). BACK TO PORT is an `<a href="/">` in a `<nav>`, styled as the old button. Scripting-off renders the same page.
   - (c) **Home:** the served wordmark `<h1>` (with its `.IO` span), version line and link `<nav>` ARE the home's elements. `ui/homeStatic.ts` adopts them (moves, never clones) once at boot and every `showHome` reuses the same nodes; the rest (canvas background, tagline, callsign, buttons, chip, gear) is built by JS as before. Before JS the opaque fixed `#app` covers the served container; `<noscript>` hides `#app` for a scripting-off reader.
   - (d) **What bites next:** `client/vite.config.ts` builds documents from client modules at config time — everything `seo/crawlable.ts` reaches must stay Node-safe at module scope (guarded by a `@vitest-environment node` test). In `serve` the markup loads through `server.ssrLoadModule` so dev stays fresh. The How to Play document is ~231 KB raw (inline styles, same strings as the old DOM builders) but ~12 KB on the wire (production serves Brotli via the Render/Cloudflare edge).
   - (e) Also this cycle (Eric, verbatim: *"ffs, just install playwright if you fucking use it"*): `playwright-core` is a client devDependency; `client/scripts/perfLib.mjs` and `readabilityCapture.mjs` no longer borrow gstack's copy. Browsers: `npx playwright-core install chromium firefox`.
