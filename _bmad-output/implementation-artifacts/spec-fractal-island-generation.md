## Intent

**Problem:** Every island in the ocean is a literal circle (`Circle {x,y,r}`), so the map reads as scattered dots rather than terrain — no coves, no channels, no ridges, and no coastline worth threading a torpedo through. Eric's ruling (2026-08-05): islands become **true polygon coastlines** generated by a **fractal** process, on an ocean that stays overwhelmingly water.

**Approach:** Replace the circle-packing generator with a fractal capsule-offset generator: each landmass is a 1–3 point **skeleton** wrapped in a boundary polygon whose outward offset is driven by periodic **midpoint-displacement** (fractal) noise. The new `Island` type carries `{x, y, r}` as its **bounding circle**, so it stays structurally assignable to `Circle` and every existing consumer keeps compiling; each consumer gains a cheap bounding-circle broadphase in front of an exact polygon test using the concave-safe primitives `shared/src/sim/silhouette.ts` already exports.

## Boundaries & Constraints

**Always:**
- `generateMap(seed, playerCap)` stays **pure and deterministic** — identical `(seed, playerCap)` yields a deep-equal map on server and client, every platform. Map geometry never travels on the wire; only `mapSeed` does.
- The **skeleton** is the push-out authority: every island polygon is star-shaped with respect to its skeleton (boundary offset strictly positive along every capsule normal), so "push away from the nearest skeleton point" is always a valid escape direction. This is what makes the no-stuck-traps invariant structural rather than hopeful.
- Every island-geometry consumer does **bounding circle first, polygon second**. No consumer may iterate polygon edges before `segCircleHit`/centre-distance rejects on `isle.r`.
- All polygon math reuses `shared/src/sim/silhouette.ts` (`pointInPolygon`, `closestPointOnPolygon`, `pointPolygonDistance`, `segPolygonDistance`, `segPolygonHit`, `polygonMaxRadius`). **Do not author a second polygon library.**
- Island-geometry branching stays confined to the existing helper functions (`losClear`, `islandClearance`, `blockedWater`, `earliestIsland`, `pushOutOf`, …). Never inline edge iteration into a `visible()`/`materialize()` row in `signals.ts` — that isolation is what keeps those rows under ESLint `complexity: 10`.
- `PROTOCOL_VERSION` bumps **25 → 26**: the same seed now yields a different map, so an un-bumped old client would build a different ocean and desync catastrophically.
- The four ratified invariants hold at **every** roster size 2–20 and are property-tested across ≥100 seeds: min channel width, no enclosed lagoons, no concave stuck-traps, spawn ring clear.

**Block If:**
- The land-coverage band 3–5% cannot be hit while all four invariants hold (i.e. the generator cannot converge) — HALT rather than silently widening the band or dropping an invariant.
- Making the LOS path polygon-exact regresses `npm run check` wall-clock by >25%, or the per-tick perception cost regresses measurably after broadphase — HALT and report rather than trading away exactness.

**Never:**
- Never change the water disk itself into a polygon — the map edge stays a circle (`aim.ts` `clampInsideMap`, `collision.ts` `clampCenter`, `zone.ts` rings all keep circle math).
- Never let render geometry diverge from sim geometry: the client draws the **same** polygon the server collides and LOS-tests against. No decorative smoothing that the sim does not honour.
- Never touch fog compositing, the storm/zone timeline, perception's five declared invariant exceptions (`sp`/`hc`/`mz`/`sunk`/`sm`), the XP economy, or any weapon tuning.
- Never add fog banks, whirlpools, or roster-scaled ocean params — those are Stories 5-4, 5-5, 6-2 and stay out of scope.
- Never modify `client/src/render/ambient.ts` (menu-only decoration, deliberately un-seeded).

## Design Notes

**Why the skeleton is load-bearing.** A landmass is a skeleton polyline `S` (1 point = blob, 2–3 points = ridge/peninsula) plus an outward offset function. Sample the capsule around `S` at `N` points (N = 32 for small, 48 for large); each sample has an outward normal. Displace sample `i` outward by `halfWidth × m_i`, where `m` is **periodic midpoint displacement**: start with 4 values, subdivide to `N`, halving amplitude by `roughness` each level. Clamp `m ∈ [0.45, 1.6]`.

Because every offset is strictly positive along a capsule normal, the polygon is **star-shaped about `S`**. Three invariants fall out for free rather than needing enforcement:
- the interior is solid — an island can never contain a lagoon;
- push-out always has a valid direction (away from the nearest point on `S`), so no concave pocket can trap a hull;
- concavity is bounded by the `m` clamp ratio (1.6 / 0.45), which is what `MAX_CONCAVITY` pins.

```
skeleton (2 pts)   capsule samples      fractal offset (m_i)
    o———————o   →   · · · · · · ·   →      ,-·-.__,-·-.
                   ·           ·         ,'           `·.
                   · · · · · · ·         `·._  ,-·._,-'
                                             `'
    blob = 1-pt skeleton · ridge = long S, small halfWidth
    archipelago = a GROUP of landmasses, gaps >= CHANNEL_MIN
```

**Archipelagos are a group concept, not a shape.** Each member is its own polygon; the group roller places 2–4 members around a common anchor with inter-member gaps drawn from `[CHANNEL_MIN, CHANNEL_MIN × 3]`. That is what produces threadable channels — a single polygon can never have them without violating star-shapedness.

**One validation, three guarantees.** Rasterize the map at 32u cells. A cell is *navigable* iff its centre is at least (widest beam / 2 + margin) from every polygon. Flood-fill navigable cells from the spawn ring. Reject the map if any non-land cell is not adjacent to a reached navigable cell. This simultaneously rejects enclosed lagoons, unreachable pockets, and channels too narrow for a Battleship — and it is deterministic, so client and server reject identically.

**Broadphase is mandatory, and it is a perf win.** `losClear` today runs inside O(ships² × islands) every tick. Polygon edge iteration there would be a real regression — but `Island.x/y/r` is a bounding circle, so `segCircleHit` rejects almost every island at the same cost as today's exact test, and edges are visited only on a bounding hit. `Island.core` (largest radius about the skeleton fully inside the polygon) gives the opposite early-out: a segment through the core is definitely blocked, no edges needed.

**Structural assignability keeps the diff honest.** `Island` carries `{x, y, r}`, so `readonly Circle[]` parameters still accept `readonly Island[]` and nothing breaks by type alone. This is deliberate — the compiler will *not* catch a missed call site, so every one of the ~20 sites in the Code Map must be visited explicitly. Treat "it still compiles" as no evidence at all.
